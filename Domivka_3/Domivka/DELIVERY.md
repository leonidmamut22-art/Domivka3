# Доставка без API-ключів користувачів

Продавець заповнює звичайний профіль відправника: прізвище та ім’я, телефон, місто й відділення. Покупець обирає товар або комплект одного продавця, вказує дані одержувача і відділення. Після підтвердження продавцем сервер автоматично пробує створити одну ТТН. Ключ Нової пошти вводить лише оператор у серверному .env.

## Що потрібно оператору

1. Отримати власний API-ключ і погодити з Новою поштою модель маркетплейсу, де фактичними відправниками та одержувачами післяплати є різні користувачі.
2. Зареєструвати погоджених відправників/контакти в підключеному акаунті. Для кожного відправника потрібна підтверджена прив’язка отримувача післяплати; звичайний номер телефону не доводить право на виплату.
3. Увімкнути NOVA_POSHTA_MARKETPLACE_ENABLED=1 лише після погодження. У NOVA_POSHTA_SELLER_MAPPINGS записати затверджені оператором відповідності Telegram ID → approved, cod_recipient_is_sender, phone, sender_ref, contact_ref. Це серверні налаштування; покупці й продавці не бачать і не вводять API-ключі.
4. Перевірити реальне контрольне відправлення і зарахування післяплати саме фактичному продавцю. Така перевірка не виконувалася без ваших облікових даних і договору.

Без цих налаштувань сервіс явно показує, що автоматична доставка очікує підключення. Замовлення працює, продавець може додати справжню ТТН зі свого застосунку. Підставні номери або оформлення всіх продавців від імені власника платформи не використовуються.

## Параметри посилки й повтори

Потрібні реальні вага та габарити. Для кошика з кількох речей — параметри всієї запакованої посилки, а не першого товару. Створення ТТН не означає фізичне відправлення, доставку або оплату. Після таймауту з невідомим результатом повтор блокується: спочатку звірте документ у кабінеті перевізника. Номер, доданий вручну, не є підтвердженням оплати.

Укрпошта наразі підтримує ручну ТТН; автоматичний API потребує окремих доступів.

Офіційні джерела: https://novaposhta.ua/for-business/cooperation/integration/ та https://novaposhta.ua/additional-services/shipping-module/ . Публічна документація не підтверджує універсального права оформлювати післяплату довільному продавцю лише за його телефоном.
