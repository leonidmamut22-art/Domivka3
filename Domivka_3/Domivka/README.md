# Domivka 4: нерухомість, маркет і клуб

Telegram-бот і мініапп з єдиною базою SQLite. Існуючі функції оренди збережено; маркет має окремі оголошення, обране, чати, замовлення, скарги та відгуки після завершених покупок.

## Запуск

1. Зробіть резервну копію наявної папки `data` та `.env`. Не завантажуйте їх у GitHub.
2. Python 3.11 або новіший: `python -m venv .venv`, активуйте середовище та виконайте `python -m pip install -r bot/requirements.txt`.
3. Скопіюйте `.env.example` у `.env`. Укажіть `BOT_TOKEN` і свій числовий Telegram ID у `ADMIN_IDS`.
4. Укажіть власника в `OWNER_ID`. Центральне підключення перевізника налаштовує оператор за [DELIVERY.md](DELIVERY.md); користувачі не вводять API-ключі.
5. Запустіть `python bot/bot.py` або відповідний `start.bat` / `start.sh`.
6. Для постійної роботи вкажіть власний стабільний HTTPS `WEBAPP_URL` через reverse proxy до локального порту 8080. Автоматичний тунель підходить для перевірки; його доступність і адреса можуть змінюватися.

Схема маркету створюється додатково в наявній базі при старті. Оголошення та бронювання нерухомості не переносяться у товари.

## Команди

- `/services` — перемикання сервісів.
- `/market [запит]` — пошук товарів.
- `/sell` — покрокова публікація товару, фотографії та підтвердження.
- `/orders` — покупки та продажі.
- `/rent` — поточне меню нерухомості.
- `/settings` — мова та налаштування.
- `/cancel` — вихід із поточного сценарію.
- `/app` — мініапп.
- `/import URL` — чернетка власного оголошення за посиланням.
- `/moderate` — черга оголошень і скарг для адміністратора.

Мова інтерфейсу маркету — українська або російська; тема — світла, темна або системна. Основні елементи та сценарії оренди також локалізовано. Частина старих додаткових текстів про Клуб, Pro та договори оренди залишається українською. Тексти оголошень, повідомлення користувачів та серверні повідомлення не перекладаються автоматично.

## Оплата і доставка

Маркет підтримує післяплату або оплату при самовивозі. Domivka не приймає оплату карткою, не утримує гроші, не є ескроу та не надає гарантію повернення коштів. Перевіряйте товар, продавця та умови перевізника. Не повідомляйте CVV, PIN або коди з SMS продавцям.

### Нова пошта

Ключ перевізника налаштовує лише оператор у серверному `.env`. Продавець заповнює звичайні дані відправника. Автоматична ТТН після підтвердження замовлення вимагає погодженої з перевізником центральної моделі відправників і післяплати; подробиці в [DELIVERY.md](DELIVERY.md). Без підключення доступна ручна справжня ТТН.

Для автоматичної накладної потрібні точні відділення відправника й отримувача, контакт відправника, ПІБ і телефон отримувача, вага та габарити посилки. У разі ручного введення адреси без довідника продавець оформлює накладну у своєму кабінеті та додає її номер вручну. Створена ТТН ще не підтверджує фактичне відправлення, отримання чи оплату.

Після неоднозначного результату API (наприклад, таймауту під час створення) повторна автоматична відправка запиту блокується. Спочатку перевірте документ у кабінеті Нової пошти, щоб не створити дублікат.

### Укрпошта

У цьому випуску: вибір перевізника у замовленні та додавання продавцем справжнього номера ТТН вручну. Автоматичне створення через API Укрпошти потребує окремого договору та доступу; його не імітовано.

## Імпорт за посиланням

Публічні сторінки DOM.RIA, OLX і mono перетворюються на редагований чернетковий опис з доступними метаданими та фото. Перед публікацією користувач має перевірити дані й підтвердити права на контент. Сторінки, що потребують входу, JavaScript або блокують завантаження, можуть не імпортуватися; доступне ручне заповнення. Імпорт не є інтеграцією з акаунтом сторонньої платформи.

## Модерація та безпека

`REQUIRE_APPROVAL=1` вмикає попередню модерацію оголошень. Адміністратори з `ADMIN_IDS` мають доступ до `/api/market/moderate`; API вимагає підписаний Telegram `X-Init`. Не публікуйте базу даних, `.env`, резервні копії, журнали з персональними даними та ключ шифрування. Налаштуйте резервне копіювання SQLite через SQLite backup API або при зупиненому процесі.

Резервування товару виконується транзакційно; ключ запиту захищає від дублювання одного замовлення. Чати й дані доставки доступні лише учасникам. Скарги та блокування не замінюють роботу адміністратора. Не позначайте продавців як перевірених без реальної перевірки.

## Перевірка

`python -m unittest discover -s tests -v`

Тести перевіряють авторизацію Telegram, розмежування доступу, резервування й повтори замовлень, імпорт та шифрування/формат запитів доставки з підміною зовнішніх відповідей. Реальне створення накладної й проходження доставки потребують окремої перевірки з вашим ключем; секрети не входять до репозиторію.

## Оновлення до Domivka 4

Зупиніть попередній процес, збережіть резервну копію data/.env, оновіть код і залежності, запустіть той самий бот заново. Саме завантаження ZIP або зміна файлів не перезапускає Telegram-бота. Перевірте /version: має бути 4.0-business. Команда /start тепер відкриває вибір двох ринків; /account, /cart, /club, /friends, /admin відкривають нові розділи.

Бізнес-модель та джерела дослідження — [BUSINESS_MODEL.md](BUSINESS_MODEL.md). Цифрові переваги за Stars — одноразова купівля на строк, без автосписання. /paysupport — підтримка оплат; PAYMENT_SUPPORT_URL має вести до реальної підтримки оператора. Доставка й оплата фізичних товарів залишаються післяплатою/самовивозом.

Адміністратори з ADMIN_IDS мають повні права; OWNER_ID — власник. Власник може призначати модераторів/маркетологів, відкликати доступ, звіряти рекламні надходження та реальні угоди для реферальних бонусів. Дії журналюються. Заявлений рекламний бюджет, підтверджені гривневі надходження, Stars та GMV угод показуються окремо.
